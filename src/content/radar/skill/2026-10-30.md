## 今日新发现

### 1. Microsoft SkillOpt-Sleep（未安装，最高优先）

Microsoft 官方开源项目（Star 约 18.8k，最近更新数小时内），其 SkillOpt-Sleep 引擎可从本地 coding agent 的历史会话中挖掘重复任务，在 held-out 验证门控下离线合并为已验证的技能与长期记忆，供人工审核采纳。官方文档明确包含针对当前 AI 工作流参考适配的参考集成路径，与本地工作区技能工坊（skill_workshop 学习技能机制）高度同构，可作为其上游参考实现。
- 局限与注意：官方 README 明确标注数据边界——真实后端会将截断的会话摘录发往所选 provider；运行前需审阅 transcript 来源。

- **来源**：GitHub microsoft/SkillOpt (docs/sleep/README.md)
- **价值判断**：官方验证门控设计 + 多技能 fan-out 事务化采纳机制，工程成熟度高（preview 状态，接口可能变动）
- **与当前栈关联**：直接对标 skill_workshop 机制；建议先读官方文档再决定是否做本地试验
- **来源等级**：official
- **来源名称**：GitHub (microsoft/SkillOpt)

### 4. Microsoft SkillOpt 主体（未安装）

SkillOpt-Sleep 的上游方法：把技能文档当作冻结 agent 的可训练参数，用带 epoch/batch/learning-rate 纪律的编辑循环优化。官方数据：在 6 个基准、7 个目标模型上覆盖 52 个评测单元；弱模型收益更大（GPT-5.4-nano 上 +11.9pt，门控开启时）。单 seed 结果，小于 1.5pt 的差异应视为噪声（官方自述）。
- 局限与注意：训练需要可检查正确性的重复任务集；本工作流任务多为一次性，适配度未确认。

- **来源**：GitHub microsoft/SkillOpt（README/CHANGELOG）
- **价值判断**：当前技能工坊的官方参考实现，值得关注其演化方向
- **与当前栈关联**：为 skill_workshop 提供上游方法论与验证门控设计参考
- **来源等级**：official
- **来源名称**：GitHub (microsoft/SkillOpt)
